# NumberShareクライアント実装記録（2026-11-16）

## 実装範囲

- 確定したローカル検知をUUID v4・固定本文で永続化し、設定済みHTTPS APIへバックグラウンド送信する。
- タイムアウト・接続失敗・429・5xxは同じイベントIDで自動再送する。認証・権限・入力・競合・削除済みイベントは自動再送を停止し、UIから再送できる。
- 送信待ち・送信済み・確認が必要な件数と直近100件をUIで確認する。
- APIの検知履歴をカーソル終端まで全件取得し、ローカルイベントIDとの一致で自分／他の利用者に分けて地図・一覧表示する。
- 開始日・終了日を指定して、端末内の検知履歴を上限で切らずに永続送信キューへ追加する。同じローカル記録は再追加せず、手動アップロードはリアルタイム送信の停止中でも処理する。
- 履歴のナンバー／照合状態／投稿範囲検索と、登録車両の一連指定番号／地域・コメント／カテゴリ検索をUIから行う。
- エンドポイント・認証キーをUIで設定する。所有者UIには保存値を返し、入力欄は既定で伏せ字、明示的に表示を選んだ場合だけ平文表示する。監査ログへ値は記録しない。

## 保存先と秘密情報

端末では `state/numbershare/config.json` と `state/numbershare/queue.json` を `config.Atomic` で0600保存する。実値をソース、テストfixture、公開ドキュメントへ含めない。リポジトリ内で利用したGoツールチェーンやブラウザー試験結果はignored `tmp/` に限定した。

外部送信は明示的に有効化された後の検知だけを対象とする。推定位置はローカル地図では利用するが、外部APIへ実測位置として送信しない。

## 内部API

| メソッド・パス | 用途 |
| --- | --- |
| `GET /api/v1/plate/share/status` | 公開設定とキュー集計・直近項目 |
| `PUT /api/v1/plate/share/config` | revision付き設定更新。キー省略は現値維持 |
| `POST /api/v1/plate/share/check` | 保存済みキーで本人情報を確認 |
| `POST /api/v1/plate/share/retry/{event_id}` | 停止項目を再送待ちへ戻す |
| `POST /api/v1/plate/share/upload` | JSTの開始日・終了日を指定してローカル履歴を重複なく送信キューへ追加 |
| `GET /api/v1/plate/share/sightings` | 共有検知の取得・ローカル所有判定・検索 |
| `GET /api/v1/plate/share/vehicles` | 登録車両検索 |

ブラウザーは外部APIへ直接接続しない。既存の同一Origin、CSRF、request ID、管理ネットワーク境界をそのまま適用する。

## 検証

- Go単体テストで、同一本文・同一イベントIDの再送、5xx後の成功、422の自動停止と手動再送、再起動後のキュー復元、認証ヘッダー、推定位置の除外、自分／他利用者の分類、5ページを超える全件取得、期間アップロードの重複防止を確認した。
- Vue型検査・本番ビルドを実行した。
- Playwrightの合成データ試験で、自分／他利用者の地図レイヤー、登録車両検索、保存キーの既定伏せ字と表示切替、設定保存、接続確認を確認した。
- 公開対象の差分に引継ぎ資料の実キー・接続先が混入していないことを文字列検索で確認する。

## 2026-11-17 main取り込み

- `origin/main` のNumberShare自動登録・独立同期サービスと更新済みナンバー認識モデルをマージした。
- 管理画面用サービスの `New` / `retryDelay` と、独立同期サービス側の同名関数が同一パッケージで衝突したため、独立同期側を `NewSyncer` / `syncRetryDelay` に明確化した。双方の送信・受信機能は残している。
- NP1上では引き続き秘密ファイルのPOSIX権限を検証する。Windowsの合成mode bitはACLを表さないため、Windows試験時だけPOSIX mode判定を除外した。
- Vue型検査・本番ビルド、Go全パッケージのtest/vet、成果物パッケージ作成に合格した。

## 2026-11-17 UI余白調整

- 共有タブの各カードで、カード全体と共通見出しの上余白が二重に適用されていた状態を解消した。共通の見出し余白は他画面と揃え、入力欄・一覧・地図は独立した本文余白内へ配置した。
- API設定は未設定時だけ初期展開し、認証キー設定済みなら初期状態を折り畳みにした。APIの全検知履歴は設定カードの直下へ移動した。
- Vue型検査・本番ビルドと、320 / 390 / 1440pxを含むナンバー画面のPlaywright試験25件に合格した。共有タブについては全5カードの並び、外側・見出し・本文の余白値、API設定の設定済み／未設定それぞれの初期開閉状態も検証している。

## 2026-11-17 main同期との統合

- 管理画面内の永続キューを唯一の検知送信ワーカーとした。main由来の `numbershare-sync` 互換モードは旧 `private/numbershare.json` を未設定時に一度だけ管理画面設定へ移行し、その後は待機するため、検知をPOSTしない。
- 自動登録と管理画面で設定ファイルを分けず、`state/numbershare/config.json` を単一の設定元にした。所有者が管理画面で変更した設定を旧設定で上書きしない。
- mainの旧設定に機器用認証キーがある場合は移行直後から初期設定済みとして扱う。初回登録欄は表示せず、匿名IDの再登録や機器用キーの再発行を行わない。
- ローカル記録IDから決定的UUID v4を生成し、通常送信と期間アップロードで共用する。ナンバー本文はmain側と同じ検証・整形を通し、一連指定番号をAPI形式（例: `12-34`）にしてから永続化する。
- リアルタイム送信は記録の最終更新から45秒待って本文を確定する。期間指定アップロードは所有者の明示操作なので待たずに送信する。成功時の照合結果は従来の `plate/numbershare-sync.json` 互換形式へ保存し、ナンバー記録画面の種別・コメント表示を維持する。
- 未設定時は共有タブに初回登録欄を表示する。匿名ユーザーID・端末名・初回登録キー・管理画面用キーを所有者が入力し、`POST users` で発行された機器用キーと復旧コード、管理画面用キーを0600設定へ保存する。匿名IDの無断自動生成は行わない。
- 管理画面用キーは既定で伏せ字とし、明示表示できる。外部管理画面はURLによるキー受渡しを実装していないため、「キーをコピーして管理画面を開く」でクリップボードへコピーして新規タブを開き、秘密値をURLへ含めない。
- 検知送信と `users/me` の接続確認は機器用キーを使い、全検知履歴の受信と登録車両検索は保存済みの管理画面用キーを優先する。実機で管理権限必須APIへ機器用キーを送ると403になることを確認したため、送信権限と管理閲覧権限を分離した。
