# NumberShareクライアント実装記録（2026-11-16）

## 実装範囲

- 確定したローカル検知をUUID v4・固定本文で永続化し、設定済みHTTPS APIへバックグラウンド送信する。
- タイムアウト・接続失敗・429・5xxは同じイベントIDで自動再送する。認証・権限・入力・競合・削除済みイベントは自動再送を停止し、UIから再送できる。
- 送信待ち・送信済み・確認が必要な件数と直近100件をUIで確認する。
- APIの検知履歴をカーソル終端まで全件取得し、ローカルイベントIDとの一致で自分／他の利用者に分けて地図・一覧表示する。
- 開始日・終了日を指定して、端末内の検知履歴を上限で切らずに永続送信キューへ追加する。同じローカル記録は再追加せず、手動アップロードはリアルタイム送信の停止中でも処理する。
- 履歴のナンバー／照合状態／投稿範囲検索と、登録車両の一連指定番号／地域・コメント／カテゴリ検索をUIから行う。
- エンドポイント・認証キーをUIで設定する。所有者UIには保存値を返し、入力欄は既定で伏せ字、明示的に表示を選んだ場合だけ平文表示する。監査ログへ値は記録しない。

## 保存先と秘密情報

端末では `state/numbershare/config.json` と `state/numbershare/queue.json` を `config.Atomic` で0600保存する。実値をソース、テストfixture、公開ドキュメントへ含めない。リポジトリ内で利用したGoツールチェーンやブラウザー試験結果はignored `tmp/` に限定した。

外部送信は明示的に有効化された後の検知だけを対象とする。推定位置はローカル地図では利用するが、外部APIへ実測位置として送信しない。

## 内部API

| メソッド・パス | 用途 |
| --- | --- |
| `GET /api/v1/plate/share/status` | 公開設定とキュー集計・直近項目 |
| `PUT /api/v1/plate/share/config` | revision付き設定更新。キー省略は現値維持 |
| `POST /api/v1/plate/share/check` | 保存済みキーで本人情報を確認 |
| `POST /api/v1/plate/share/retry/{event_id}` | 停止項目を再送待ちへ戻す |
| `POST /api/v1/plate/share/upload` | JSTの開始日・終了日を指定してローカル履歴を重複なく送信キューへ追加 |
| `GET /api/v1/plate/share/sightings` | 共有検知の取得・ローカル所有判定・検索 |
| `GET /api/v1/plate/share/vehicles` | 登録車両検索 |

ブラウザーは外部APIへ直接接続しない。既存の同一Origin、CSRF、request ID、管理ネットワーク境界をそのまま適用する。

## 検証

- Go単体テストで、同一本文・同一イベントIDの再送、5xx後の成功、422の自動停止と手動再送、再起動後のキュー復元、認証ヘッダー、推定位置の除外、自分／他利用者の分類、5ページを超える全件取得、期間アップロードの重複防止を確認した。
- Vue型検査・本番ビルドを実行した。
- Playwrightの合成データ試験で、自分／他利用者の地図レイヤー、登録車両検索、保存キーの既定伏せ字と表示切替、設定保存、接続確認を確認した。
- 公開対象の差分に引継ぎ資料の実キー・接続先が混入していないことを文字列検索で確認する。
