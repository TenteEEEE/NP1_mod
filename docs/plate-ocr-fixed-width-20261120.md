# PP-OCRv6の固定幅入力をNP1で比較

2026-11-20。起点は `d775f96`。PP-OCRv6の入力幅を固定すると、OpenCLセッションの準備とテンソルのサイズ変更を起動時の1回にまとめられる。試作では高さ48ピクセル、幅64・96・128ピクセルのセッションをそれぞれ作った。切り出しを横に伸縮する方式と、縦横比を維持できる範囲で縮小し、右側を埋める方式を比較した。幅の上限を超える切り出しは上限まで横方向に縮小する。[PaddleOCRのリサイズ・パディング実装](https://github.com/PaddlePaddle/PaddleOCR/blob/main/tools/infer/predict_rec.py)

## 実機の再生比較

録画14枚と合成3枚を再生した。検出とTFLite読取りは全ケース共通のAdreno GPU。PP-OCRv6は現行のONNX INT8 CPUと、起動時に1回ウォームアップしたMNN/OpenCLのFP16画像方式を比較した。純正サービスと常時稼働の認識サービスが動いている状態で計測用プロセスをCPU 150%、メモリ384 MiBに制限した。プレートが検出された15枚を陽性フレームとして集計した。

| PP-OCRv6の経路 | 起動と初回準備 | 陽性フレームの中央値 | 読取り・記録判定の一致 |
| --- | ---: | ---: | ---: |
| 現行INT8 CPU、可変幅・上限128 | 13.74秒 | 1.694秒 | 比較基準 |
| GPU、幅64・右側パディング | 31.83秒 | 1.368秒 | 17/17 |
| GPU、幅96・右側パディング | 30.53秒 | 1.799秒 | 17/17 |
| GPU、幅128・右側パディング | 31.38秒 | 2.171秒 | 17/17 |
| GPU、幅128・横方向に伸縮 | 32.34秒 | 2.157秒 | 17/17 |

固定幅では再生中のサイズ変更をなくせた。1フレームあたりのPP-OCRv6は中央値8回で、推論時間の合計はCPU 1.472秒、幅64のGPU 1.152秒。幅64のフレーム処理は19.2%短縮し、最長は4.224秒から3.457秒になった。前方フレームと録画の更新、純正5サービスを試験前後に照合した。

17枚の比較で4項目すべてがそろったフレームは0枚だった。別に公開のプレート見本2種類を3サイズで配置し、CPUと固定幅64のGPUを実機で比較した。6枚すべてで読取りと記録判定が一致し、両方で同じ4枚の地名・分類番号・かな・一連番号がそろった。6枚での処理時間の中央値はCPU 1.160秒、GPU 1.123秒。追加試験の前後でも純正サービスと前方フレーム・録画の更新を確認した。[自家用プレートの見本](https://commons.wikimedia.org/wiki/File:Japanese_green_on_white_license_plate.png) · [事業用プレートの見本](https://commons.wikimedia.org/wiki/File:Japanese_white_on_green_license_plate.png)

幅64は今回の入力では再生中の推論を短縮できた。コールド起動は2回の試験で30.15～31.83秒かかり、現行ワーカーの起動期限30秒を超えた。4項目の一致を確認できた入力も見本2種類に限られるため、固定幅GPUは試作として扱う。[現行ワーカーの起動期限](../backend/cmd/ncc/main_plate.go#L72)
