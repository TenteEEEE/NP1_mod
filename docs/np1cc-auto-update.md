# NP1 Control Center の自動更新

NP1CC 0.5.0から、GitHub Releasesで配布する署名済みの互換更新をNP1本体から取得できます。0.5.0では、最初にADBでNP1CCと更新サービスを導入します。

## 管理画面

「システム › 設定・バックアップ › NP1 Control Center の更新」で現在のバージョン、候補、変更内容、容量、最終確認、適用結果を確認できます。

| モード | 動作 |
| --- | --- |
| 新バージョンがあれば即時更新 | 適用できる安定版を取得、検証し、稼働中に適用します。 |
| ダウンロードし、次回起動時に更新 | 検証済みのバイナリを保存し、本体を次に起動したときに適用します。 |
| 更新確認のみ（既定） | リリースと署名済みの更新情報を確認し、適用できる版を表示します。 |
| 更新しない | 定期確認、ダウンロード、自動適用を停止します。 |

定期確認の間隔は約6時間です。通信などの一時的なエラーは15分後を目安に再試行します。次回起動の判定にはLinuxの起動IDを使います。Webサービスの再起動や画面のリロード後も予約は維持されます。別のモードに切り替えると次回起動の予約が取り消されます。

「更新を確認」「即時更新を実行」は全モードで使えます。即時更新は確認後に更新を探し、予約済みのパッケージがあればそのパッケージを適用します。適用中は管理画面とライブ表示が一時切断されます。

「Wi-Fiのみ」が既定です。リリース確認、名前解決、ダウンロードの接続先インターフェースをNP1のWi-Fi（`wlan0`）に固定します。Wi-Fiから接続できなければ待機表示になります。「Wi-Fi と 4G を許可」に切り替えると、NP1の通常の回線選択で接続します。純正ファームウェアの管理は別パネルの「純正ソフトウェアの更新抑止」にあります。 [管理画面の使い方](usage.md)

## 初回導入

1. 所有者PCでビルドするか、信頼できる配布元の導入パッケージを `artifacts/ncc/` に展開します。 [既存の導入手順](installation.md)
2. 既存の導入手順で0.5.0を配備し、稼働と録画を確認します。
3. 配布者から信頼できる経路で取得したEd25519公開鍵を指定して、更新サービスを登録します。既定の配布元は公開リポジトリ `sochov/NP1_mod` です。別の公開リポジトリを所有者が選ぶ場合は `--update-repository OWNER/REPO` を指定します。

```powershell
python tools/deploy.py --serial SERIAL --action update-install --update-key-file PATH/np1cc-update-ed25519.pub
```

導入スクリプトは、稼働中のNP1CCとビルド成果物が一致していることを確認し、`/overlay/owner-apps/np1-control/updates/` に公開鍵・設定・検証スクリプトを保管します。署名検証の設定は所有者がrootで管理します。更新サービスを導入するとUIに設定が表示されます。

## GitHub Releaseの登録

所有者PCの現行ビルドでは、Web UIを埋め込んだ `linux/arm64` の `artifacts/ncc/bin/ncc` を生成します。実機用ビルドには所有者が用意する純正付属のリンク用材料が必要です。材料は配布パッケージの対象外です。 [録画フックのビルド契約](recorder-build-contract-20261119.md)

Pythonの `cryptography` とEd25519 PKCS#8 PEMの秘密鍵を用意し、ビルド後に次を実行します。秘密鍵は所有者のアクセス制限のある領域に保管します。

```powershell
python tools/package-np1cc-release.py --key PATH/release-ed25519.pem --out artifacts/releases/v0.5.0
```

`v0.5.0` のReleaseには、このフォルダの導入用ZIP、導入情報と署名、公開鍵を添付します。0.5.0は更新サービスの初回導入版です。以後の版で互換更新を配布する場合は、更新元として実機で互換性を確認した旧版の `ncc` を `--from-binary PATH/ncc` で追加指定します。複数指定できます。この場合は更新用の `np1cc-update-linux-arm64.gz`、`np1cc-update.json`、`np1cc-update.json.sig` が追加で生成されます。署名したタグは固定し、修正は新しいバージョンで公開します。 [GitHub ReleasesのAPI](https://docs.github.com/en/rest/releases/releases)

## 更新の範囲と復旧

更新元バイナリ、対象の純正構成、録画フックと注入器、候補バイナリの組合せが一致する場合に適用します。ナンバー認識のモデルやネイティブ補助バイナリ、unit、ルーティング、互換性を失うデータ移行を伴う更新にはADBでの配備を使います。リリースの安定版タグが対象です。通信処理は非特権で動作し、適用前に公開鍵の署名、サイズ、SHA-256、バージョン、バイナリの自己検査を確認します。 [更新・復旧手順](recovery.md)

既存バイナリ、復旧情報を永続化してから、NP1CCのバイナリを切り替えます。Web、broker、純正OTAの監視役を再起動し、HTTP/HTTPS、録画フックの応答、関連サービスの稼働状態と本体側のバイナリを確認して確定します。検証が失敗した場合や確定前に電源が落ちた場合は、直前のバイナリに戻します。復旧情報と直前のコピーは本体の `updates/` にあります。既存の設定と利用者データは引き続き使われます。
