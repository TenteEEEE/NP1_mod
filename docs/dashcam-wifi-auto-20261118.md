# ドラレコ録画設定と自動回線時のWi-Fi操作

## 録画

- ドラレコ再生の「録画設定」から、前方と車内／後方それぞれの1080p／720pと、録画への車内音声の有無を操作できる。純正設定と同じ照会・変更・再照会の経路を使う。
- 再生中の各ファイルについて、MP4の映像トラックのサンプルサイズの合計とトラック長から平均ビットレートを計算する。音声やMP4コンテナのバイト数は計算に含めない。必要なメタデータが不足する場合は非表示。
- 対応ファームウェアと公式ガイドで確認できる録画設定は、カメラ別の画質プリセットと音声記録など。任意の録画ビットレート、H.264の詳細パラメーター、車内／後方の常時録画だけを停止する純正設定は確認できなかった。「純正サービスによる車内カメラの利用」は別の設定で、録画停止として流用できない。既存の保存サンプルを `ffprobe` で確認したところ、前方・車内ともに1080p・H.264 Baselineで、平均映像レートはそれぞれ約10.12 Mbps・1.24 Mbpsだった。値はそのファイルの実測。 [Pioneer クラウドドライブレコーダー設定](https://jpn.pioneer/ja/support/manual/np/np-001/usersguide/7C94DA4A6A143781BDDC680AE10CF5B7.php)

## Wi-Fi

- 導入済みの版は、自動モードが4Gへ切り替えた状態でSTAソケットを開けず、接続一覧がHTTP 503になる。STAが稼働している場合も、スキャン要求の直後にキャッシュを取得していた。NCCに保存した接続先は、純正supplicantの再起動後に復元していなかった。
- 自動モードでは、検索・接続操作が一時的にSTAを起動する。検索はsupplicantの完了通知を待ち、回線が切れた場合も再接続後に結果を取得できるよう、結果を2分間だけメモリーに保持する。接続の確定は対象ID、SSID、IPv4の照会後に行い、保留中は自動切替を抑止する。検索だけだった場合、接続を取り消した場合、または確定期限までに接続できなかった場合は、開始前の回線状態へ戻す。4G固定ではSTAを起動しない。
- NCC保存先はSTA停止中も表示できる。純正supplicantが起動すると、NCC保存済みプロファイルをメモリー上に復元する。自動復帰ではWi-Fiのリンクとデフォルト経路を確認し、再試行の時間を制限する。
- 4GからWi-Fiを起動するとTailscaleの通信が一時的に切れ得る。実機での接続設定は、すでに接続済みの端末からNP1の管理用ホットスポットで操作を継続できる。

## 配備と検証

- Vueの型検査と本番ビルド、Go全パッケージのテストとvet、Python 143件、Wi-Fi・録画・純正設定・再生地図のPlaywright 34件に合格。ARM64向けNCCと331ファイルの配布マニフェストを生成した。
- 指定先のHTTPSで、自動モード、4G経路、STA停止、接続一覧のHTTP 503を確認した。純正録画の照会では前方・車内の高画質と音声記録ONを確認した。変更系リクエストは送信していない。
- 対応版の更新は配布物上の `sh tools/web-worker-update.sh --uplink` を使う。旧NCCバイナリを復旧領域へ保存し、Web・broker・回線監視の更新とハッシュ一致を確認する。失敗時は旧バイナリを復元する。純正Communication／DriveRec／ImageRecog／Voice／QMMFおよびNCCの主要ワーカーは更新前後の状態と起動IDを比較する。
- 指定先で利用できたのはHTTPSの管理画面とAPI。録画再生の実機試験は現行版の録画一覧が `NO_SD` を返したため、再生確認へ進めなかった。配備に必要な管理シェルへは接続できず、実機の更新と、更新後のスキャン・Wi-Fi接続・4G復帰、録画設定を書き換えた後の新規録画は未検証。
