# 録画フックのビルドローカル契約（2026-11-19）

## 原因

録画フックとランタイム注入器は独自Cソースから生成していたが、NP1CC側には特定のClangで生成した成果物のSHA-256とread-backシンボル位置をソース定数として固定していた。別PCのClang 22/23で同じソースを生成すると、正当な成果物でもバイナリ配置やハッシュが変わり、NP1CCの固定値と一致しなかった。

## 修正

- 全ネイティブ成果物の生成をGoビルドより前へ移動した。
- `verify-recorder-artifacts.py`が、そのビルドで生成したフックSHA-256、注入器SHA-256、read-backシンボル位置をELFから取得する。
- Goビルドは3値を`-ldflags -X`でNP1CCバイナリ内の未公開変数へ埋め込む。
- ソース上の既定値は空とし、契約値を埋め込まないWeb専用ビルドでは録画詳細設定をfail-closedで無効にする。
- ビルド後にAArch64 NP1CCバイナリへ3値が実際に埋め込まれたことを再検証する。
- 実機導入時のself-testと、導入後の`hookLoaded` / `applied` read-backは従来どおり必須とする。

純正DriveRecは対応SHA-256と命令位置の検証材料、純正sysrootはリンク用材料としてignoredな`resources/`だけで使用する。純正バイナリ、純正ライブラリ、生成したフックと注入器はGitへ追加しない。
