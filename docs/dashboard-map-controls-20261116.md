# ダッシュボード地図の右端と現在地アイコン

## 変更

出典表示と現在地ボタンの右位置に、ライブ映像パネルなどで覆われる幅 `--hero-pad-right` を加えていたため、横長画面で右端から数百px左へ寄っていた。背景地図全体の右端から12pxへ固定し、現在地ボタンを出典表示の少し上に揃えた。地図の中心調整に使うinsetは引き続き位置計算だけに使う。

アイコンは照準の `LocateFixed` から、青い塗りの現在地矢印 `Navigation` へ変更。44pxの操作領域、アイコンのみの表示、アクセシブルな名前、追従の再開動作は保持する。

追加指示に従い、走行グラフの初期選択は7日へ戻した。24時間は引き続き選択でき、横軸はJSTの0・3・6・9…の3時間刻みを数字だけで表示する。現在時刻に含まれる分を各ラベルへ繰り返す表示を廃止し、ラベルの時刻に対応した軸位置へ置く。0時から翌0時の期間なら0〜24の9目盛となる。地図の経路は過去24時間を維持する。

## 導入・復旧計画

最新mainを取得し `93cbfdb` のままであることを確認。`fix/journey-history-map-24h` で既存のGPS保存保証修正も含めてビルドし、`tools/deploy.py --serial <指定serial> --action journey-update` から反映する。Web/brokerだけを更新し、バイナリとNCC状態を退避、read-backを行う。利用者によるNP1再起動後の状態を基準として、純正5サービスとAP/modem/native/plateの同一性を比較する。WindowsのWi-Fiと純正設定は変更しない。

初回の `journey-update` は、再起動後のSDが未マウントのため電波履歴修復で失敗し、元のバイナリ・NCCログへ自動復旧した。今回のWeb表示修正とGPS保存保証はSDへの書込や過去ログ修復を必要としないため、最終版は `--action web-worker-update` を使用する。独自のWeb/broker更新だけを行い、別途9サービス全ての同一性とバイナリSHA-256を再確認する。

## 検証

1440×900と2618×1886で、地図フレームの右端から両要素までが12pxであること、出典の上にボタンがありクリックできることをブラウザーで検証する。中間幅・スマートフォンの既存操作も確認し、ビルド・Go全テスト/vet・Pythonテストの後、実機へ導入して同じ位置関係を確認する。

実データの地図・録画・接続情報・実機の識別子はignored `tmp/` に記録する。

## 結果

- 最終版を `web-worker-update` で実機へ反映。配布バイナリ、インストール先、実行用、WebプロセスのSHA-256一致を確認した。
- フロントエンド本番ビルド、Go全テスト・vet、パッケージ検査に合格。Python全139件、関連ブラウザー28件、軸と右端配置の最終確認5件に合格した。
- 実機ブラウザー6件に合格。1440pxと2618pxで右端から12px、出典の上に現在地ボタン、アイコンの塗り、ボタン操作を確認した。7日の初期選択、24時間選択後の数字だけの3時間目盛、過去24時間の地図、1000/1200pxの6枚下寄せ、スマートフォンの地図移動と復帰を検証した。実機のスクリーンショットも目視確認した。
- 11/13〜11/15の距離・時間を維持し、更新前の11/15の18,408 GPS点すべての時刻・座標が更新後も一致した。再起動後の基準に対し、純正5サービスとAP/modem/native/plateの計9サービスのPID・InvocationIDは変化していない。
- `hardware_verify.py --camera` はSDの未マウントにより動画一覧の取得でHTTP 400となり完走していない。別の読取確認で前方・車内の実JPEGを取得できた。SD録画の動作合格やGPSの現在測位成功とは報告していない。

過去11/14の細かい座標列の復元は未完了のまま。今回の画面修正と今後の座標保存の修正を、過去分の復元成功と混同しない。
