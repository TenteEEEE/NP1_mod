# 高度化PICSの実験機能

NP1 Control Centerで「システム → 設定・バックアップ → 高度化PICS（実験機能）」を開きます。初期状態では受信と表示がオン、VOICEVOXと進行方向の絞り込みはオフです。ダッシュボードのライブ映像直下からも設定を開けます。

## 発話と音声キャッシュ

- 残り時間の目安が得られると「青まであとおよそ27秒です」のように案内し、約10秒前と5、4、3、2、1秒を読み上げます。
- 残り時間が不明で、連続受信した同じ交差点の二灯のうち元から赤だった候補が一つの場合、他方の青点滅で「別方向の信号が青点滅しています」、他方が赤に変わったら「まもなく青になる見込みです」と案内します。対象灯器の赤→青が受信できた時点で「信号が青になりました」と発話します。
- 共通のVOICEVOX設定で、対象の声の定型文と1〜99秒を組み立てるための45クリップを本体に保存します。設定で音量と試聴を確認できます。声を変えると不足分を準備します。

Type 2の残り値は1〜8の段階です。同じ交差点・灯器・段階で青までの観測値5件がそろい、その差が2秒以内の場合に、中央値から秒数の目安を表示します。 [参照実装の表示仕様](https://github.com/yumu19/ble-pics-viewer/blob/d97a27872ef1251a743fe8c1d5eadf0058e553a6/web/README.md#表示内容)

## 受信記録・地図・周期

設定欄の「受信記録・地図・周期」を開き、日本時間の日付と交差点を選びます。灯色や段階が変わったときと、同じ状態が続く場合は15秒ごとに記録します。地図では青い点がNP1の受信地点、橙の点がType 1で得られた交差点位置です。位置が取れなくても灯器番号・灯色・段階・受信時の残秒の目安を記録します。位置情報が欠けている場合は、録画のNMEAに時刻差3秒以内の有効な測位があれば履歴表示時に照合します。

同じ灯器で一回の赤→青から次の赤→青まで、受信が継続した区間だけを一周として測ります。灯色ごとの実測中央値と回数を表示します。直近5回が2秒以内にそろうと予測周期も表示します。保存の上限は一日約2 MiB、全体約48 MiBです。

進行方向は受信直前の最大3分のGPSから求めます。3点で16 m以上移動し、途中の向きがそろう測位を使います。停車している場合は停車直前の移動区間を使います。絞り込みをオンにする場合は「受信記録・地図・周期」から交差点を選び、現地で確認した灯器ごとの横断方向を真北0°の方位で登録します。横断方向と進行方向を約25°以内で照合します。方向が未確定の灯器は受信履歴で確認できます。 [警察庁 高度化PICS運用ガイドライン](https://www.npa.go.jp/laws/notification/koutuu/kisei/kisei20260310.pdf#page=5)

## 純正Bluetoothと自動再接続

NP1の純正 `NEventWatcherCom` が提供する `NPBTLEHandler` に、本体ブローカーが2秒の受動探索を要求します。探索終了の通知を受け取って次の要求へ進みます。周囲に広告がない場合も、純正サービスが探索の終了を通知すれば「受信待ち」と表示します。広告の送信アドレスは本体内の一時IDに変換します。

探索の拒否、接続切断、8秒間の通知途絶を検知すると、受信状態と進行中の発話をいったん取り消します。純正サービスへの要求は1秒から最大15秒まで待ち時間を広げて再試行します。受信が戻ったら新着の灯色から案内を再開します。同一送信元で完成済みの段階別の学習値は保持し、受信が途切れた区間は個別の灯色変化や周期に使いません。設定をオフにすると要求を止めます。純正Bluetoothの起動と停止は純正側の管理に従います。

## 実機で確認した範囲

起動ログには純正 `qca_fw_loader` のファームウェア読み込みが一度成功し、その後に純正スタックが停止した記録がありました。試験で純正Bluetoothの起動を要求した2回は、コントローラーからUARTでHCI応答が来ず `-110` でタイムアウトしました。これは再起動要求時の事象で、原因の確定には至っていません。 [Linuxのエラー定義](https://github.com/torvalds/linux/blob/master/include/uapi/asm-generic/errno.h)

162PCの赤と青の試験広告は独立した受信機で確認しました。NP1では探索要求が拒否され、広告受信から発話までの通し試験は残っています。準備したVOICEVOXの45クリップは、模擬入力を使いNP1の本体スピーカー出力で再生を確認しました。受動探索の状態、通知途絶、再接続、古い信号の無効化は自動テストで検証します。

実機には `tools/device/web-worker-update.sh` で所有者用Webとブローカーを更新しました。保存済みの旧版バイナリーを復旧に利用できます。稼働中のWeb・ブローカーのバイナリーと純正6サービスの同一性を確認し、実機の設定画面と履歴、前方・車内のJPEGおよびSD録画のMP4範囲読み取りを確認しました。純正バスを読み取り専用で観測し、探索の拒否が続く間にも稼働中のブローカーが受動探索を再試行することを確認しました。現時点の実機の受信履歴は0件です。
