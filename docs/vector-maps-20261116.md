# 地図のベクトルタイル化

## 対象と表示方針

ダッシュボードの現在地、走行履歴マップ、録画再生の経路、ナンバー記録の4か所をLeafletの画像タイルからMapLibre GL JSへ移行する。地図データはキー不要のOpenFreeMapのOpenMapTiles形式ベクトルタイルを使う。ライブラリーとworkerはNCCから配布し、外部スクリプトは実行しない。

縮小時は主要道路・都市名を中心にし、拡大すると生活道路（ズーム13）、建物（14）、施設名（15、17以上で対象拡大）、番地（17）を段階的に表示する。日本語の名称を優先する。経路や電波、条件に合致したナンバーは背景よりはっきりした色で表示する。

システム → 設定・バックアップ → 表示設定で、ダッシュボード／走行履歴／録画再生／ナンバー記録を独立して選択できる。選択肢は「UIに合わせる」「ミスト · 青灰色」「ナイト · 濃紺」「セージ · 緑灰色」「カラー · 標準地図風」。カラーは緑の森林・青い水域・ピンクの高速道路・黄色の主要道路など、以前の地図に近い多色の構成。設定は本体に保存し、旧設定・旧バックアップでは全画面autoを補完する。バックアップの復元でも画面別の選択を保持する。

実測点列・欠測区間・選択時刻は保持し、表示の間引きをGPSデータの削除に使わない。地図の移動、拡大縮小、現在地への復帰、電波重畳のオン／オフ、録画位置との連動を維持する。

## 一覧・操作の修正

- ナンバー記録の一覧に日本時間の日付・曜日と当日の表示件数の区切りを追加。最新日が先頭。絞り込みに追従し、一覧内のスクロールでは日付を上部に保持する。UTCの15時が日本時間の翌日になる境界を検証。
- ダッシュボードの走行グラフでは期間ボタンを折り返さず、「日毎」の集約選択を「カスタム」の右に保持。幅が足りない場合は期間部分だけ横スクロールし、ページ自体の横はみ出しを防ぐ。
- ダッシュボードのホイール／ピンチは地図中央を基準に拡大縮小する。MapLibreの既に有効なhandlerはenableでオプションを書き換えられないため、disable後に中央基準でenableする。
- 背景地図をオフにしてもGPSのGeoJSONを保持。スタイルの切替で点列・カメラ位置を削除しない。GeoJSONのtoleranceを0にして、記録された細かい座標を表示用の処理で間引かない。欠測区間同士は接続しない。

## 導入と検証

依存ライセンス・CSP・worker配布を更新する。4画面の実際のWebGL描画・操作・明暗・ズーム別の情報量、ネットワーク障害時の経路保持、地図の背景を消した場合の動作を検証する。ビルド・Go全テスト/vet・Pythonテストの後、既存の `web-worker-update` でNCCのWeb/brokerだけを実機へ反映し、バックアップ、バイナリread-back、純正5サービスを含む9サービスの同一性を確認する。WindowsのWi-Fiや純正設定は変更しない。

ライセンス台帳は133件。MapLibreのworkerを同じオリジンのハッシュ付きアセットとして配布し、CSPではworker-src self、タイル取得先だけをconnect-srcに許可する。unsafe-evalは追加しない。実際のMVTを用いるブラウザーテストで、建物等の描画・ズームによる非表示・4色の変更後のGPS座標保持を確認する。表示設定の保存・画面再読込、背景取得失敗時の経路描画も対象。

`tools/build.ps1`（Vue型検査、フロントビルド、Go全テスト/vet、arm64ビルド、ライセンス検証・パッケージ）とPython全139テストは合格。

ブラウザー検証は68ケース合格、実機専用の4ケースはローカル実行ではskip。画面幅320〜2,618 px、各テーマ、日付境界・絞り込み、画面別設定の保存と再読込、GPS全座標保持、電波オン／オフ、背景地図の取得失敗、ポップアップ、録画時刻連動、ホイール／ピンチ／1本指ドラッグを確認した。開発サーバーのHMR後も同じMapLibreインスタンスを検査できるよう、DEV限定のWeakMapはhot.dataに保持する。生の測位座標を本番DOMへ追加しない。

実機には `web-worker-update` で導入済み。更新スクリプトが旧バイナリをrecovery配下へバックアップし、障害時に旧バイナリへ戻す手順を維持。更新後にインストール先・run領域・実行中Webプロセスの3か所と配布物のSHA-256一致を確認。純正Communication／DriveRec／ImageRecog／Voice／QMMFとNCC AP／modem／native／plateの計9サービスのPID・InvocationID・状態は更新前と一致した。前方・車内カメラはJPEG実データを取得できた。11/13〜15の距離・時間と11/15の18,408個の測位点の座標は更新前後で一致。

実機ブラウザー試験9ケース合格。実際の外部ベクトルタイルと同一オリジンworkerのHTTP成功、CSP、4色への切替、11/13の復元元3,320測位点との一致、11/13・14の日別表示、電波切替、24時間窓とパン保持、中間幅6パネルの下寄せ、右端の帰属表示・現在地ボタン、スマートフォンのドラッグを確認した。スクリーンショットと実機read-back資料はignored tmpに保存した。

再起動後の実機ではSDが未マウントで、`hardware_verify.py --camera` の録画一覧検査はHTTP 400となる。この状態を地図改修の合格に置き換えず、独立保存のGPS経路とカメラ直接APIで今回の機能を検証した。SDや純正サービスの設定は変更していない。mainは再取得して93cbfdbのままで、作業ブランチはこれを包含している。

11/14の過去経路は引き続き実測資料からのみ回収する。本体保持NMEA6本は回収済みSDコピーと同一で、新たな全点列の発見ではない。旧集計から座標を生成して復元済みにはしない。追加の調査結果と復元できた範囲を別途記録する。

追加で本体の `/pio_log/rw/ERASABLE/booting_journal` にある約18 MiBのログも読み取り専用で確認したが、RMC/GGAの候補は0件。11/14は保存済み57.6221 km・5,335秒と、回収できた82測位点／48区間を保持している。全走行の詳細点列は発見できておらず、完全復元とは扱わない。
