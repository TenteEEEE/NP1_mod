# 純正アプリの本体操作・SDフォーマット

純正設定画面のAlexa直下に「本体の操作」を追加。最優先はSDフォーマットのWeb操作で、BTで受け取った要求を処理する純正DriveRecへ、独自クライアントから同じCommonFreeStyle IPCを送る。純正プロセスへのコード注入やバイナリ改変、raw block書込み、mkfsは行わない。

## SDフォーマット

- 純正の挿入状態・フォーマット状態を照会し、挿入済み・処理中でない場合だけ確認を開始する。
- sysfsのtypeがSDのカードを一意に特定。内蔵MMCは除外する。CIDと容量から非公開hashを計算し、1分有効・一回用のランダム確認tokenに結び付ける。
- 画面では容量と消去範囲を表示し、全消去へのチェックと「SDカードを消去」の文字入力を必須にする。
- サーバーでtokenの期限・再利用・カード交換を拒否。ヘルパーも送信直前に同じカードhashを照合する。
- 実際の要求はDriveRecの `0601/0001`（空payload）を1回だけ送る。送信前後に `0601/0002`、`0601/0004` を使う。PID・プロセス起動時刻・InvocationID・firmware hash・応答nonce/function/opcodeを照合する。
- HTTP 202は「要求受付」であり、`completionConfirmed=false`。処理状態が非処理中へ戻っただけでは成功とみなさず、本体の案内で結果を確認する。タイムアウト時の自動再送は禁止。
- 本体内へ独立保存したNCC走行履歴・設定を削除する処理はない。SDの実消去試験は行わず、カード識別と確認画面までを実機で検証する。

## 他の本体操作

録画品質（前方・車内）、音声記録、日時／速度／位置の記録、イベント衝撃感度、駐車中の衝撃感度・監視・録画時間、車種・車内の広さ・集音方向、取付方向、音量の13項目を固定IDの純正要求と再照会で操作する。変更前の値を照合し、対象以外の値の変化も検査する。取付高さ・位置と角度判定は読取り。特殊な未設定値は未設定と表示する。既存の消音・音量補正画面も同画面へ配置。

新規ヘルパーは `tools/build-native-operations-helper.py` でWasmの応答解析試験、arm64ビルド、SDKガードを検査する。既存の安全なprocess-local SDK runtimeを再利用する。純正共有メモリやサービスの初期化・停止を行わない。ヘルパー自身の期限で参照とロックを解除し、実行中に外部から強制killしない。

`tools/probe-native-operations.py --serial ...` で6種の照会とカードhashの相互一致を実機確認。`--same-value` では10 setterへ現在値と同じ値を送り、照合済み応答と再照会を確認。純正7サービスとSetting.DATは不変。これは実値を別の値に変えるroundtrip試験や、実フォーマット試験とは区別する。

Goでは確認不足・期限切れ・カード交換・二重実行・受信失敗・設定readback不一致を検証。ブラウザーでは320／1440 pxで確認・キャンセル・失敗時の非再送・期限切れとAlexa直下の配置を検証。更新用スクリプトは追加ヘルパーのバックアップ・元の不在状態への復旧も対象とする。

## 続行する範囲

ユーザー指定の `docs_private/NP1-Bluetooth-BLE-command-reference-20261116.md` を一次参照に、ローカル保存のMy NP1 1.6.3 APKと逆コンパイル資料を照合する。既知のBT操作の追加を優先する。未同定・存在のみのopcodeを実行可能にしたり、OTA確認から自動更新する要求を送ったりしない。クラウドのアカウント操作とは分ける。

クラウド契約・目的地検索・購入等はMy NP1の案内を残す。本体側で形式を確定できた操作は、下記の実行可能なカードへ追加した。全BLEの輸送・認証手続きを汎用raw APIとして公開するものではない。

参照：[公式ドライブレコーダー設定とSDフォーマット](https://jpn.pioneer/ja/support/manual/np/np-001/usersguide/7C94DA4A6A143781BDDC680AE10CF5B7.php)、[公式本体連携](https://jpn.pioneer/ja/support/manual/np/np-001/usersguide/DF00E87DC78822401BC97A91F16258A2.php) 。

## APK照合

ローカル保存のMy NP1 1.6.3（97,656,039 bytes、SHA-256 `70ab84bc1190f08f157f4582b74915d72f4da8159bd313ba93238738903ae460`）のJADX出力を読み取り。`jc.b`（DriveRecorderSettingOperationSystemManager）のfunction=1537、要求／応答組1/32769・2/32770・3/32771・4/32772と、32773の最終結果notifyを確認した。要求受付のboolと最終結果notifyは別のcallbackであり、受付だけを完了表示しない設計と整合する。純正APKや逆コンパイル本文はGitに追加しない。

## SD優先分の導入結果

native worker更新とWeb/broker更新を既存スクリプトで実施。元のunit・バイナリ・ヘルパーをrecoveryへ退避し、異常時に元の不在状態も含めて戻す手順を検証した。最終の画面調整だけのビルドではnative workerを再起動せず、直前に導入した既知のworker hashと、新しいWeb/broker hashをそれぞれread-back照合している。

実機ブラウザーで、SDの挿入・非処理中の応答、容量を含む全消去確認ダイアログ、キャンセル、モバイルの横はみ出しがないことを確認。送信した変更系APIはprepareだけで、executeは0件。実フォーマットは未試験。

更新前後の純正Communication／DriveRec／ImageRecog／Voice／QMMFとNCC AP／modem／plateの8サービスはPID・InvocationID・状態が一致。11/13〜15の距離・時間と11/15の18,408測位点の座標は一致し、前方・車内カメラのJPEGを取得できた。資料・スクリーンショットはignored tmpへ保存。

Vue型検査・フロントbuild・Go全テスト/vet・ライセンス確認は合格。Python全139件、および追加ヘルパーの復旧を含めたnative updaterの4件を確認。ブラウザーでは既存Alexa・音声・純正設定との20件に加え、期限切れを含むSDの5件と、実機の非消去確認1件が合格。実機で見つかった音声設定の初回照会との競合は、照会中のSD操作を一時無効にして解消した。高さ740 pxのスマートフォンでも確認ボタンへスクロールできる。

## SD以外の操作とグリッドUI

Alexa直下の操作を機能別のカードにまとめた。幅に応じて複数列、スマートフォンでは1列。SD、設定、音声、以下の追加操作とクラウド案内を同じグリッドへ配置する。

| カード | 操作 | 本体の処理先 |
| --- | --- | --- |
| 取付の調整 | 開始・中止・完了、7秒毎の接続維持、前方／車内の切替、調整用AP情報、リアウインドウ学習状態／リセット | DriveRec / ImageRecog |
| GNSS・センサー | アンテナ・測位・衛星数、センサー学習クリア | SitAwrEng |
| ライセンス・診断 | OSSライセンスと診断ログのSD転送 | System |
| 保守・シリアル | モード照会、物理キー待受、パスワード送信、待受終了、シリアル状態と入出力切替 | System |
| 本体のナビ操作 | 同期済みルートの案内開始・更新・終了・道路切替 | Navigation |
| 本体アカウントの操作 | ログイン、チェックイン、オーナーキー照会 | Setting |
| セットアップ | 車両設定の状態・完了通知、初期設定の状態通知、本体初期化 | Setting |
| 純正Wi-Fi接続 | 状態・ON/OFF・詳細・保存一覧・周辺一覧・接続中SSID・削除・自動接続・新規／保存AP接続・切断・初期化 | Communication |
| 純正ローカルAP | 状態・開始／停止・車内判定・対応方式・SSID／認証／帯域／パスワード変更・初期化 | Communication |

APKの `p8` / `k7` の列挙と生成メッセージを照合し、資料で未同定だったWi-Fi STA `/8` は自動接続、AP `/3` は車内判定、`/5` は対応方式、`/6` は初期化と確認。保存AP・周辺APの応答は最大5件の入れ子メッセージとして解析する。

FW7のSystemの埋込みschemaを使い、OSS・保守・診断・シリアルの所有プロセスも特定した。ヘルパーは所有プロセスの実行ファイルhash・PID・起動時刻、応答の送信元・nonce・function・opcodeとクリーンアップを確認する。固定action名だけを受け付け、任意function/opcodeやファイルパスは受け付けない。

パスワード、トークン、氏名等は標準入力でヘルパーへ渡し、argv・ディスクログ・監査本文に残さない。画面の入力は送信開始時に消去し、応答にはno-storeを付ける。シリアル変更は変更前の値とPoseidonモードを検査し、変更後に状態を再取得して一致を確認する。Wi-Fi接続要求はSTAのONを確認する。接続要求の受付をDHCP・疎通の成功とは表示しない。通常のWi-Fi画面にある接続確認・復旧機能も利用できる。

全変更に確認画面を設け、本体初期化には確認文字も要求する。notifyのみの操作は `acknowledged=false`、`completionConfirmed=false`。OSS・診断転送にはSDのマウントを確認し、応答のboolだけでファイルや録画再開まで合格とはしない。取付の接続維持は画面を離れると停止する。

### 照合で見つかった修正・制限

- 車両・マイクは `0401`。旧実装の `0A00` はあおり運転検出用だったため修正した。取付方向は `0700/2`、音量は `0400/2` を使用する。純正設定のあおり運転検出機能は既存の検証済み経路を維持する。
- センサートリップ照会／リセットはAPK・schemaにはあるが、FW7のSitAwrEngの `0xDA3B0` の分岐は `0301/1` のみを処理する。`/3` の相関応答も実機で得られなかった。両操作は理由を示して無効化し、成功を模擬しない。
- 取付高さ・位置は特殊な未設定値を含むため読取りとする。単位・許容範囲を未確認のまま書込まない。
- 純正OTAの4操作は表示するが、プロジェクト規則のrootfs・純正サービス変更禁止により実行不可。特に確認要求から自動適用へ進み得るため、読取り試験でも送らない。
- BLE接続用のchallenge・token交換・AMA等のphone接続通知やresponse-only領域は、Webの認証やユーザー操作とは別。意味の未確定なopcodeやログイン済みクラウドAPIをダミー操作に置き換えない。

### 追加検証

9グループの設定照会と、GNSS・リアウインドウ学習・保守モード・車両設定完了・純正STA/AP・シリアルの10照会で相関応答と参照解放を確認。純正9サービスのidentityを比較する。10 setterの同値送信では、一度Setting.DATの一時差分を観測したが、追加の読取りで元の内容と一致した。上書き復旧やsetter再送はせず、検証スクリプトは非同期保存後の最終ファイルも保存・照合するようにした。

ホスト検証では、固定action／protobuf入力制約、応答相関、入れ子AP一覧、不正応答、確認不足、保守前提、再照会不一致、初期化notifyと完了の区別を検査。ブラウザーでは320／1440 pxの列数と横はみ出し、認証情報の確認、失敗時の非再送、初期化の確認文字も検査する。消去・初期化・接続切替・保守入退場を試験で自動実行しない。

追加の同値送信10件と純正9サービス・保存設定の最終比較は合格。導入後の実機ブラウザーではグリッド、SD確認のキャンセル、GNSS・学習状態・保守・STA/AP照会を確認。変更系通信はSDのprepareだけで、execute・初期化・接続切替は0件。保存済みWi-Fiのページ照会も実HTTP 200で入れ子データを取得できた。純正STAがOFFの実機では周辺一覧が応答しないことを確認し、ONを前提として検査するよう修正した。試験のために無線をONにすることはしない。

ビルド・Go全テスト/vet・ライセンス照合、Python139件、音声UI8件と本体操作UI9件、実機UIの非消去試験を実施。native/Webの更新前後で本体サービスidentityと、11/13〜15の走行集計・11/15の18,408点を照合し、前方・車内JPEGを取得した。実消去、実初期化、実ネットワーク切替、保守入退場、クラウド認証、OSS/ログの実転送、ナビ開始等の変更効果の実機試験は行っていない。
