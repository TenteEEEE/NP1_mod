# 小さく写ったナンバーの読取りと地名偏りの評価

対象は `numbershare-reader-v7-lowres-v6s`（r4）です。r2は少数車両の連続フレームを一様に抽出した学習により、千葉系を既定値のように出力していました。40px前後の判読できない幅でも正解の文字を強制したため、地名・分類・かなを推測する癖もありました。実写の地名は47種類で、撮影地域の千葉周辺に偏っています。r3は重み付けで偏りを抑えましたが、小さい幅の誤答が残りました。千葉系は千葉・市原・成田・袖ケ浦・習志野・市川・船橋・野田・柏・松戸・土浦を指します。

## r4で変えたこと

PP-OCRv6 smallを土台に変更しました。出力は273文字で辞書は共通です。約34px未満は空欄を正解とし、46pxまで損失の重みを上げることで、判読できない幅では出力しない学習を行いました。車両グループ・地名・かなでも重み付けしています。事業用の「あ」は実写で5台しかなく、「あ→み」の誤読があったためです。

架空の文字で生成した写実的な合成画像304枚（115地名）と、撮影条件を変えた編集画像563枚（夜間の対向車ライト・雨・夕方の逆光・トンネル照明）を追加しました。VLMで全項目を読み戻せたものだけを使用し、評価データと同じ読みは除外しました。

## 11月15〜17日の走行映像

VLMの読みは参考であり、人手による正解ではありません。VLMが「多摩」と読んだ7台は画像確認で実際は「相模」で、VLMの誤りでした。相模が多いのは撮影地によります。

## 評価キット（2026-11-14）

現行エンジンをコンテナ内のCPUで実行し、2回検出または信頼度0.7以上・幅45px以上の1回検出で記録しました。一連番号の読取り器はplate-v2で変更なしです。記録の正答率はr3と同じ93.7%（誤9・正しく記録した車120台）で、camAは96.2%、camBは93.1%、np1は88.6%でした。一連番号の誤記録の改善はこの評価キットでのみ計測しています。

信頼度0.6以上・幅70px以上の地名出力では、np1の千葉系はr3の2.9%からr4の1.6%になり、日光は69から60フレームになりました。日光は上段が判読できない1台に集中しており、残課題です。camBの千葉系出力の大半は実際に千葉ナンバーを付けた1台です。r4はその車の一部フレームを土浦と読みますが、同じ車の多数決では千葉です。

## 記録時のガードと残る確認

地名・分類番号・かなは、既定で幅70px以上の異なる2フレーム以上で同じ値が出て、有効なフレームの2/3以上を占める場合に採用します。条件照合と発話にもその値を使い、一致しなければ空欄にします。フレーム同士の誤読が一致する場合は防げません。

エンジンには `numberOverrideConfidence` と `numberVetoScore` の任意設定があります。省略時は追加の信頼度上限・低スコア拒否を行わず、従来の動作を維持します。詳細は [開発・検証](development.md#textocr設定) を参照してください。

残る課題は、日光を出す1台、55px以下の少数の「あ→み」誤読、相模を他地名と読むフレーム（採用は1台）、人手確認のないVLM参照、実機でのかなの差です。
